# M12 — the Roadhouse furniture moves from paint to props

Branch `opus/roadhouse-m12-props-own`, cut from `main` (`4a8bf55`). Worktree `.worktrees/m12`.
Not pushed. Option A, as the lead decided from the M11 evidence: where `world/props.json`
has a prop for a piece of Roadhouse furniture, the prop **is** the furniture and
`js/roadhouse-art.js` stops painting it.

`GAME.PROPS_ENABLED` is now **true** in `index.html`. `js/props-production.js` was not
touched: Deep's below-actors band is on `deep/props-below-band` and **has not landed in
`main`**, so `roadhouse-stage-01` still draws over the Giant and the giant-stage coverage
line is the one red assertion left. Details under Gates.

## 4. The flag

`index.html` and `test/retro-scene.html` both set `GAME.PROPS_ENABLED = true` before
`js/props-production.js` loads. The module still defaults to `false` when nobody sets it,
so the switch survives.

`test/props-flag-off.js` was rewritten around the new default, because its old premise —
"flag off renders exactly as before M9" — no longer has a referent:

- **A** this tree, flag forced **off** → the painted shell alone
- **B** a copy with the prop layer deleted outright → `A == B` byte for byte
- **C** the page as it ships → must **differ** from A
- **D** the page with the flag forced **true** → must equal C

11 checks, green. The old "byte-identical to a shot from `main`" arm is gone: `main`
still paints the furniture, so that comparison would now be asserting the bug.

`world-builder.html` needs no flag. It loads `js/props.gen.js` for the M10b editor but not
`js/props-production.js`, and the Builder draws its own preview.

**Where the room reads worse than the M11 on-shot:** nowhere in composition — M11's shot
was the duplicated room, which was strictly worse. Two things are worse than the **painted
room on `main`**, and they are honest losses:

1. **The neon no longer flickers.** `js/roadhouse-art.js` drove it as a function of
   `nowMs()` over the painted sign's own pixels; the prop is a static frame, so the whole
   mechanism (`neonFlicker`, its schedule and targets) is deleted. The room lost its only
   piece of ambient motion. Restoring it means either an animated prop or a paint pass
   that knows the prop's geometry — neither is in this milestone's fence.
2. **Furniture no longer casts contact shadows.** `drawShadow` anchored each painted piece
   to the floor with a three-row shadow. Props carry no shadow, so tables and chairs sit a
   little flatter. The floor pools (still painted, re-aimed at the prop anchors) carry most
   of the weight, but it is a real loss of grounding.

**The two red lines in `props-production-chrome`, both known:**

1. `roadhouse-giant-stage: no actor loses more than half its sprite` — the Giant is 55 %
   covered by `roadhouse-stage-01`. This is exactly what `deep/props-below-band` exists to
   fix, and that branch **has not landed in `main`** (checked: not merged, head `15a26be`).
   Nothing in this milestone can close it without touching `js/props-production.js`.
   Note for the lead: that branch also edits `test/props-production-chrome.js`, so it will
   conflict with this one.
2. `runtime: M10a's three depth hooks are the outermost sprite functions` — carried from
   M11 unchanged. The outermost wrappers are `js/traincar-scene.js`'s; they call through,
   and every depth assertion now passes, but the M10a proof was taken on
   `test/retro-scene.html` and still deserves a pass on the production page.

Every other depth line is green, including the ones M11 reported red.

**A side effect worth recording:** the room got cheaper to draw. `js/roadhouse-art.js`
went from ~2 000 rectangles a frame to 1 107, and the harness's frame cost on the same
machine fell from M11's 28.6 ms median to **17.5 ms flag off / 17.8 ms flag on**. The prop
layer still costs ~0.3 ms; the paint it replaced cost far more than that.

One Chrome driver at a time; none left behind.
