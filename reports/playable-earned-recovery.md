# Playable Build 01: recovery against earned durable progress

This is a separate acceptance layer on the complete unseeded route, not an alternative seeded route. Run `CAMPAIGN_RECOVERY=1 node test/campaign-playthrough.js`. The default route is unchanged; invalid flag values fail before browser startup. Both modes retain exclusive/no-overwrite evidence handling.

The recovery variant repeats the already-earned opening diary dialogue, reloads after the physical awakening and Act 3/4 boundaries, cancels the still-uncommitted tape choice after the six admissions, reloads and resumes it through Leland's actual body, and reloads again at the Lodge handoff. It then continues physically through the Lodge and final epilogue to the real ending and title. All seven named recovery checks must execute exactly once before the report can say PASS.

Before reloading, the host waits for an idle frame whose actual classic save, narrative envelope, generation metadata, fingerprint and optional finale checkpoint agree with live observed state. It reloads the same isolated browser profile, uses the real Continue input if the game shows the title, and allows the finale's normal direct resume. It never invokes New Game during restoration. It compares the restored durable ledger, evidence, position, objective and authored cast placements; it deliberately does not require wandering NPCs to preserve arbitrary pixel positions. No game state or storage is injected or edited by the route.

The host checker has 39 local fixture contracts covering absent/stale/mismatched saves, invalid identity, unfinished writes, generation/fingerprint mismatch, mutable observations, corrupted after-state, cast drift and dropped recovery cases. The existing 16 route, 66 browser boundary and evidence-overwrite checks also pass locally. These are not browser-recovery results. The read-only hosted workflow must complete the whole earned route with all recovery checks before this PR becomes ready.

Storage fault injection for the terminal write is separately covered by `test/finale-completion-persistence.js`; it is not disguised as a clean player journey. Exhaustive storage faults, physical Safari/Android testing, every story branch and uncoached human usability are not claimed. Human playtest: NOT_RUN. No production behavior, locked story text, main merge, deployment or Vault synchronization is changed by this test PR.
